# eval

Labelled sets and the eval runner for jev vs Claude (M0·3). The eval answers one
question: at what probability should jev's answer be accepted, and how often must
Claude catch the rest? Thresholds are model-specific, so every jev version
needs a fresh run.

## Files

| File | What it is |
| --- | --- |
| `data/articles.candidates.jsonl` | ~350 recent articles: headline, short snippet, link, source, time, gazetteer candidates. Never full text. |
| `data/pairs.candidates.jsonl` | ~350 story-pair candidates: shared entities/terms plus random pairs |
| `data/match.candidates.jsonl` | 20 alert-prompt candidates, derived from article categories (`derived: true`) |
| `data/articles.labels.jsonl` | seeded agent labels (30, provisional) |
| `data/pairs.labels.jsonl` | seeded agent labels (30 pairs, 10 marked duplicate) |
| `data/articles.labels.human.jsonl` | human labels; preferred over the seed per article id |
| `data/pairs.labels.human.jsonl` | human labels; preferred over the seed per pair id |
| `data/seed_labels.py` | the record of the seeded decisions, not a labelling shortcut |
| `report.md` / `report.json` | generated by `make eval` (gitignored) |

`eval/data/.cache/geonames` holds the downloaded GeoNames files and is
gitignored. The committed candidates are a snapshot; feeds move, so
`make eval-collect` is a reviewed operation, not part of `make eval`.

## Collect

```sh
make eval-collect
```

It pulls a handful of public RSS feeds (BBC, Al Jazeera, DW, NPR, Guardian, ABC,
France 24, CBC, Sky, EuroNews, UN News, CNA, NYT, Washington Post, Japan Times,
Africanews, SCMP, Times of India, The Hindu), keeps items from the last 21 days,
and stores only the headline, a ≤400-character snippet, the link, the source and
the time. Duplicate URLs are dropped. The gazetteer is a minimal matcher over
GeoNames `cities15000` plus country names; it is not a geocoder and M2·1
replaces it. Plot accuracy is bounded by its candidate recall.

`make eval-collect` also regenerates the match set from the current article
labels (`go run ./eval/cmd/collect -matches-only`).

## Label

```sh
make eval-label LABELER=human:your-name SET=articles
make eval-label LABELER=human:your-name SET=pairs
```

The CLI is resumable: it skips ids already in the output file, and appends each
label as soon as you answer. `q` quits at any prompt; `s` skips an item.

- **Articles**: category (number or key), primary place (candidate number or
  `n` for none), precision (`c` country, `r` region, `t` city, `s` street,
  `p` point), parties (candidate numbers, comma-separated, or none).
- **Pairs**: `y` related / `n` not related / `d` same-event duplicate. For a
  related pair, type (`c` causal, `r` reaction, `t` thematic), direction
  (`a`, `b`, `u`) and strength (0–3).

A link connects two **distinct events**: one affects, causes or responds to the
other (directly or through an indirect chain), or both share a specific
condition or theme. Same-event coverage is **not** a link (the Clusterer merges
those) and broad/coincidental topic overlap is not a link either. The causal
type is symmetric in A/B; direction is a separate question. Every question is
self-contained because jev answers them independently.

Duplicate pairs are coverage of the same event by two outlets. The eval records
them with `duplicate: true` and excludes them from the relation metrics.
`eval/testdata/relate_contrast.json` holds contrast fixtures for same-event,
specific-theme, broad-topic, indirect-chain and reversed-causal pairs.

### Label honesty

- `--labeler` is required and must start with `human:` or `agent:`.
- An agent label defaults to `provisional: true`; do not remove it.
- A non-provisional label whose labeler is not `human:` is rejected by the
  loader. Never label agent work as human.
- The committed seed (30 articles, 30 pairs) was labelled by
  `agent:deepseek-v4.1-flash` and is provisional. It is a smoke set, not the
  tuning set.
- The full ~300 article and ~300 pair human labelling is a follow-up. Run the
  CLI with `LABELER=human:<your name>`; the human file overrides the seed for
  the same id, so the seed does not need deleting.
- The seed deliberately covers clear cases and includes some no-place and
  duplicate pairs. It is not a random sample, and the report says so.

## Run

```sh
make eval
go run ./eval/cmd/eval -config config -data eval/data
```

With keys in the environment it runs live:

| Key | Backend |
| --- | --- |
| `OPENROUTER_API_KEY` | jev through OpenRouter (the supported path) |
| `ANTHROPIC_API_KEY` | Claude Haiku for the baseline (`DOR_CLAUDE_BASE_URL` overrides the endpoint for compatible fakes) |
| `TYPESAFE_API_KEY` | **not supported alone**: it needs `DOR_JEV_BASE_URL`, `DOR_JEV_PATH` and `DOR_JEV_REQUEST_SHAPE=openrouter-decisions`, and the direct `/v1/systemone` shape is not implemented. The CLI fails early with a clear message. |

If only one key is present, that backend runs live and the other runs as a
mock; the report marks it as a mixed run. If none is present, both are mocks and
the first line is:

```
MOCK BACKENDS — NOT A MEASUREMENT
```

Mock mode points the real jev HTTP client and the real Claude SDK at in-process
fake endpoints. It exercises encoding, retries, response parsing, fail-closed
arms and the cache usage fields. It measures nothing about either model. Mock
runs never select thresholds; `config/thresholds.yaml` stays at its starting
values.

Cost: before a live run the command estimates every request with the actual
builders for the backends that will run live, and refuses if the total exceeds
`budget.eval_usd` in `config/budget.yaml` (default $2.00) unless
`-allow-over-cap` is passed. `eval_usd: 0` denies live evals outright; it never
falls back to `daily_usd`. Reservations are exactly-once: each store keeps a `pending` map keyed by
reservation id, `Record` removes the daily and token entries in independent CAS
updates, and a retry after a partial success completes the unfinished phase.
Entries older than `pending_ttl` (15m default) are eligible for best-effort
collection and stay charged at the estimate. Until the deferred GC bookkeeping
fix, an aborted update does not persist pruning, and `StaleCollected` counts
attempted removals, including aborted updates and CAS retries. The same in-memory limiter caps actual spend on mixed and
fully live runs. Its token buckets are enlarged for the batch run;
`eval_usd` is the binding limit. A live backend that returns no usable answers
makes the command exit non-zero after writing the report. Claude cost is estimated from the
price schedule in `config/models.yaml` (marked provisional); jev cost comes from
`usage.cost`.

A live run writes selected thresholds to `config/thresholds.yaml` unless
`-write-thresholds=false`. It always sets `provisional: true`, the label source,
the sample counts and the date.

## Reading the report

For each task and backend: accuracy over answered and over all labelled items,
event-probability calibration, decision-confidence calibration at the task
threshold, accuracy/precision/recall-vs-coverage or strictness curves, total
latency p50/p95, final-attempt latency p50/p95, cost per 1k items and
token/cache counts.

- **Event calibration** is probability against observed truth.
- **Decision calibration** uses the confidence for the answer that was given,
  never flipped. For jev binary questions that is p for a predicted yes and
  1−p for a predicted no; Claude's self-reported confidence already means
  P(this answer is correct), so it is used directly (relatedness AND type for
  relate). Choice tasks report selected-option calibration; binary tasks
  (match, relate) report both. Relatedness calibration is separate from type
  correctness.
- **Probability, not concentration**: gates and thresholds use P(selected), not
  jev's `confidence` (a normalized concentration). `mean_concentration` is
  reported separately.
- `$/1k` divides total cost by labelled items (N), not answered items, so
  refusals and errors are included. Latency is the whole logical call including
  retries/backoff; `last` is the final attempt.
- Claude's eval schemas ask for a self-reported confidence; it is a soft
  decision signal, not an API probability. Threshold selection uses jev only.

The fallback projection uses one record per labelled article. Errors, refusals,
missing answers and missing ids count as fallback and stay in the denominator.
`CombinePlot` returns `Fallback=true` for a missing, refused, unknown or invalid
primary, a `none` pick, a missing probability, or a missing/invalid precision.
`eval_usd: 0` denies live evals; the preflight covers only live backends and is
enforced whenever either backend is live. A live backend that returns no usable
answers makes the command exit non-zero after writing the report.

Claude wire schemas are sanitized: the structured-outputs API rejects
`maxItems`, `maxLength`, `minimum`, `maximum` and similar keywords. The
constraint moves into the field description and is enforced by Go after
decoding (`*llm.SchemaError`). `llm.ValidateSchema` is fail-closed: it rejects
`format`, `const`, `multipleOf`, `allOf`/`anyOf`/`oneOf`/`not`, `$ref`/`$defs`
and open objects instead of silently weakening them. The mock Messages server
rejects an unsanitized or invalid schema with 400, the way the real API does.

Threshold selection picks, per question, the lowest threshold where accepted
cases reach the target and at least 10 cases are accepted:

| Question | Target |
| --- | --- |
| place pick (`plot.primary`) | ≥ 90% correct on accepted cases |
| relation type (`relate.accept`) | ≥ 85% correct on accepted cases |
| Claude fallback (classify + plot union) | < 15% |

If no threshold reaches a target, the runner keeps the most accurate one and
marks `met: false`. It never claims a target was met. The starting values in
`config/thresholds.yaml` are the plan's guesses; they are not tuned values until
a human-labelled live run replaces them.

Known limits:

- The gazetteer is minimal: regions and states are usually missing, and a name
  must appear capitalised in the text.
- Alert-prompt labels are derived from categories, not independently judged.
- Claude cost is a schedule estimate, not an invoice. Cached input is priced at
  the documented 0.1x read / 1.25x write multiples of input by default.
- The seed labels are agent labels. Do not use the report as a model
  comparison until the human set exists.
